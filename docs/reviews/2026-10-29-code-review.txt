CONFIRMED FINDINGS

1. P1 — Session writes can partially save, and retries change totals again.
   services/api/src/vl_api/repo.py:180–224
   Progress, review cards, daily totals, streak, leaderboard and global statistics
   are separate writes, with no transaction or request idempotency. The practice
   UI explicitly offers a retry. Replaying one identical session produced two
   attempts and two answers. A simulated failure after progress/cards were saved,
   followed by retry, permanently lost the first-completion bonus and daily lesson
   count: the retry awarded 1 point instead of 11. Review submissions have similar
   multi-write/replay risks.
   Direction: persist a request ID and use atomic or recoverable writes so a retry
   returns the original outcome instead of applying the operation again.

2. P1 — The AWS deployment role can grant itself administrator permissions.
   infra/terraform/bootstrap/main.tf:180–184; own role name at :204
   iam:PutRolePolicy and iam:AttachRolePolicy apply to role/vl-*, which includes
   vl-github-deploy itself. There is no permissions boundary or policy allowlist.
   A holder of deployment credentials can add unrestricted permissions to itself;
   UpdateAssumeRolePolicy can also change trust. The comment claiming the name
   prefix prevents broader grants is incorrect. This was established statically;
   no cloud exploitation was attempted. External organization policies could
   restrict it, but none are defined in this project.
   Direction: exclude CI/bootstrap roles from deployment IAM management and use
   protected boundaries/allowlists on application roles and PassRole. Merely
   excluding the deploy role while allowing unrestricted new roles is insufficient.
   AWS references:
   https://docs.aws.amazon.com/IAM/latest/UserGuide/access_controlling.html
   https://docs.aws.amazon.com/IAM/latest/UserGuide/access_policies_boundaries.html

3. P2 — The supposedly read-only PR plan role can overwrite production state.
   infra/terraform/bootstrap/main.tf:133–159
   The plan role receives s3:PutObject and s3:DeleteObject on every state object.
   The PR workflow assumes this role before executing PR-controlled Terraform.
   A same-repository PR execution with OIDC permission can therefore alter/delete
   production state. The plan command uses -lock=false, so lock-file writes do not
   justify these permissions. Exposure to fork PRs depends on GitHub settings;
   this review does not assert arbitrary public-fork access.
   Direction: grant the plan role only necessary state reads; isolate state-lock
   permissions if locking is later enabled.

4. P2 — Leaderboard opt-out leaves the existing public entry visible.
   services/api/src/vl_api/repo.py:96–121
   Settings updates touch PROFILE but do not remove existing leaderboard index
   keys. The public row remained identical after setting lbOptIn=false in a Moto
   reproduction. Cleanup only happens during later positive-scoring activity;
   prior-week rows can remain until expiration. Pseudonym updates also stay stale.
   The existing opt-out test hides the defect by recording another session before
   checking visibility.
   Direction: apply privacy/name changes to existing leaderboard entries directly.

5. P2 — Abandoned signup cannot be resumed through the UI.
   apps/web/src/lib/auth.ts:121–129
   Requesting an initial signup code then refreshing loses the pending state.
   Entering the email again results in UsernameExistsException, then InitiateAuth
   for an unconfirmed user, which returns UserNotConfirmedException. There is no
   confirmation-code resend/recovery path. The actual requestCode function was
   reproduced with stub Cognito responses; a live Cognito pool was not used.
   Direction: handle unconfirmed accounts and resend confirmation codes; preserve
   sufficient state to resume confirmation.
   AWS reference:
   https://docs.aws.amazon.com/cognito-user-identity-pools/latest/APIReference/API_InitiateAuth.html

6. P2 — A crafted sign-in next parameter redirects off-site.
   apps/web/src/islands/SignIn.tsx:60
   The string guard accepts /\evil.example even though the browser URL parser
   resolves it to https://evil.example/. Example link:
   /signin/?next=%2F%5Cevil.example
   A successful login then navigates to the external destination. This is an open
   redirect; this finding does not assert that tokens are sent to that destination.
   Direction: parse the destination against location.origin and compare origins.

7. P2 — Signed-in Mark as read does not update account progress.
   apps/web/src/pages/course/[module]/[lesson].astro:117–123
   The handler only writes localStorage. Server merging happens only during
   explicit sign-in in islands/SignIn.tsx:10–14. Reading another lesson while
   already signed in does not update the dashboard or another device.
   Direction: save account read status when the action occurs and reconcile it
   when restoring a session.

8. P2 — One card can count as 100 reviews in one request.
   services/api/src/vl_api/repo.py:251–275
   Review processing only checks that the card exists. It does not enforce unique
   card IDs or due eligibility. A reproduction supplied the same card 100 times
   with rating=3 and ms=0: the API accepted 100 successful reviews, incremented its
   review count to 100, awarded points, and repeatedly modified its schedule.
   Direction: reject duplicate/ineligible card submissions and protect against
   replay/concurrent updates. This is separate from the documented choice to
   accept client-reported exercise correctness.

9. P2 — A failed final review save has no recovery action.
   apps/web/src/islands/ReviewSession.tsx:56–63, :82
   Ratings remain in memory until the end of the batch. A network/API error shows
   only an error message; there is no retry. Refreshing loses the submitted batch
   from the browser, requiring the learner to repeat the work if it never saved.
   Direction: retain pending submissions and provide a retry after server-side
   idempotency is in place.

10. P2 — The pratyahara builder ignores which h was selected.
    apps/web/src/islands/ShivaBoard.tsx:48–52
    packages/engine/src/varna.ts:86
    Selecting h in the fourteenth Shiva sutra and the following l marker highlights
    only that final h, but returns all 33 consonants. The island passes only the
    sound and the engine selects its first occurrence. This was reproduced with
    the actual engine and exact island selection logic.
    Direction: preserve the selected start slot/sutra through expansion.

11. P2 — The sam + ra... exception is broader than its grammatical context.
    packages/engine/src/halsandhi.ts:137
    The /^rA[jw]/ condition skips anusvara for sam + rajita, rajitum and rajitavyam.
    The cited Kashika explicitly gives samrajita/samrajitum/samrajitavyam with
    anusvara (saṃrājitā, saṃrājitum, saṃrājitavyam) as cases where the specific kvip
    exception does not apply. The engine instead keeps m. The existing sam + rat
    success case does not cover these counterexamples.
    Direction: require the actual exception context instead of a word prefix.
    Primary source, record 83025:
    https://github.com/ashtadhyayi-com/data/blob/master/sutraani/kashika.txt

12. P2 — Independent nam... words are incorrectly treated as suffixes.
    packages/engine/src/halsandhi.ts:258
    suffix || /^[nR]Am/.test(post) makes assimilation compulsory for tad + nāma,
    even with suffix=false. It returns tannāma and omits optional tadnāma; its
    explanation calls the independent noun/particle a suffix. The prefix test
    also catches longer nām... words.
    Direction: honor explicit grammatical context rather than infer suffixhood
    from the spelling prefix.

13. P2 — Upcoming lesson drafts are built and publicly linked anyway.
    apps/web/src/pages/course/[module]/[lesson].astro:7–12, :21–32
    getStaticPaths builds every lesson regardless of module status; previous/next
    navigation also includes every lesson. The five hal-sandhi lessons are in the
    generated sitemap despite the module being marked soon. PROGRESS records
    outstanding corrections in ru.mdx, and those passages remain in the source.
    For example ru.mdx:54 conflates the ru replacement and nasalization steps;
    :61 says every consonant although the quoted examples cover four. This is
    unfinished content being exposed by routes/navigation, not just a missing
    exercise warning.
    Direction: filter unpublished modules consistently in routes, navigation and
    sitemap, or complete and review the content before publishing it.

14. P2 — Invalid review limits produce server errors.
    services/api/src/vl_api/app.py:210
    limit=abc raises an uncaught ValueError. Zero and negative values reach DynamoDB
    as invalid limits. Reproduced through the existing handler fixture.
    Direction: validate integer limits in the range 1–100 and return a 400 response.

15. P2 (Windows development) — Timezone data is undeclared.
    services/api/pyproject.toml:8–13
    services/api/src/vl_api/domain.py:21
    A clean Windows environment cannot resolve ZoneInfo("UTC") or America/New_York
    with the declared dependencies. Five API tests failed and session persistence
    raised ZoneInfoNotFoundError. Adding tzdata only to the isolated test environment
    made all 22 API tests pass. This does not establish a Linux Lambda failure;
    Linux environments commonly provide the system timezone database.
    Direction: declare platform-appropriate tzdata for reproducible Windows setup.

FOLLOW-UP END-TO-END FINDINGS

16. P2 — CI can report a failed Terraform plan as successful.
    .github/workflows/ci.yml:131
    The plan command is piped to tee without pipefail or an explicit shell:bash.
    GitHub's unspecified Ubuntu shell uses bash -e; the successful tee and summary
    commands can hide Terraform's failure. A local shell reproduction returned
    exit 0 without pipefail and exit 1 with it.
    Direction: use shell:bash or explicitly preserve pipeline failure status.
    Primary reference:
    https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#jobsjob_idstepsshell

17. P2 — Accounts-enabled PR plans do not have the Lambda archive they require.
    .github/workflows/ci.yml:107–132
    infra/terraform/modules/api/main.tf:114
    The plan job neither builds services/api/dist/vl-api.zip nor downloads it.
    With accounts_enabled=true, filebase64sha256 requires that absent ignored
    file. An offline Terraform mock plan reproduced the missing-file failure.
    The separate API job does not publish the archive as a downloadable artifact.
    Finding 16 can conceal this failure behind a green plan job.
    Direction: build or transfer the exact Lambda archive before planning.

18. P2 — A temporary refresh outage causes persistent local sign-out.
    apps/web/src/lib/auth.ts:165–168
    Any non-success HTTP response, including 503, clears the saved-session flag.
    A Chromium reproduction restored the fake service after a 503, reloaded, and
    still got the guest screen with no new refresh attempt.
    Direction: distinguish authentication rejection from retryable service errors.

19. P2 — The documented analytics switch does not install an analytics beacon.

    Setting CF_BEACON_TOKEN only expands the Terraform CSP allowlist. The token is
    not supplied to browser code and no Cloudflare beacon exists in the build.
    Direction: implement the documented feature or remove its switch-on claim.
